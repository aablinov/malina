# ADR-005. Серверно-авторитарный бой по образцу Quake 3

- **Статус:** принято
- **Дата:** 04.11.2026
- **Заменяет:** раздел «Отложенные решения» в [adr-001-dungeon-roguelite.md](adr-001-dungeon-roguelite.md) (хост-авторитарная модель) и версии 1.0–1.4 [design-multiplayer.md](design-multiplayer.md)

## Контекст

Общий бой в версиях 1.0–1.4 считал браузер хоста: сервер ретранслировал непрозрачные сообщения, доверял хосту итог и каждому игроку — награду. На этом выросли миграция хоста посреди боя, куклы у гостя, отдельные сообщения на малину, отброс и наборы, два пути симуляции; проверить всё это можно было только Playwright-прогоном на два-три браузера (≈2 мин, нестабильно). Сид от сервера нигде не использовался.

## Решение

Как в Quake 3: сервер крутит игру на фиксированном такте, клиенты шлют команды ввода, получают дельта-снимки, предсказывают своего героя и интерполируют остальных.

- **Симуляция** — один код для сервера и браузера. Правила обороны, башни, стены, куст, кучки — чистая часть `src/sim/` (без сцены, DOM, `Math.random`, страж `server/test/sim-boundary.test.ts`). Герой, снаряжение с магией и мобы — те же классы, что в браузере, **без рендера** (`src/headless.ts`): three в Node, канвас-заглушка, `nullFx` с таймерами. Переписывать 9000 строн геймплея вслепую не стали.
- **Детерминизм** — игровая случайность только через `rnd()` (`src/rng.ts`), на время шага мира — генератор мира с сидом; один сид и те же команды дают тот же бой (тесты сверяют хэши).
- **Сеть** — `Channel` (надёжная и ненадёжная полосы, seq/ack) над транспортом (WebSocket, петля в памяти), `SnapshotRing`/`SnapshotView` (дельты от подтверждённого снимка, полный при потере), отдельный WebSocket `/game`; лобби, чат и профили — на `/ws`, как раньше.
- **Матч** (`src/game/match.ts`) — герои партии по профилям с сервера, команды по одной на такт 1/60, кадр 50 мс и снимок 20 Гц, награды считает сервер; хост — только корона и права в лобби, бой не прерывается его уходом.
- **Клиент** (`src/cgame/`) — вью по записям сущностей и событиям; свой герой предсказан и сверяется по подтверждённому вводу; чужие герои и враги — куклы по снимку с буфером 0,1 с по времени сервера. Клиент хранит кольцо принятых состояний (как `cl.snapshots`): дельта от прежней базы применяется, а не отбрасывается. Сверка слоёв с Quake 3 и что ещё не перенесено — [arch-layers.md](arch-layers.md).
- **Тесты** — `npm run test:net` на `node:test` за секунды: канал, кодек, симуляция, безголовый бой, матч над петлёй, комнаты; Playwright — один дымовой сценарий на два браузера.

## Последствия

- Чит хоста невозможен: позиции, здоровье, волны, казна и награды — у сервера; клиент видит только снимки.
- Одиночная игра идёт тем же сим-кодом локально (мир степается на странице), сетевая — по снимкам; вид один и тот же.
- Сервер тратит CPU на бой: мир без рендера, мобы думают каждый такт; матчей на процесс — пока без лимита (см. риски в плане).
- Задержка ближнего боя ≈ RTT/2: взмах виден сразу, попадание решает сервер. Лаг-компенсация — при необходимости (`Cmd.serverTime` можно добавить без смены формата).
- Лишнее снесено: `CoopHost/CoopGuest`, `battle.host`, `battle.end`, `battle.loot`, `relay`, `party.ts`; `PROTOCOL = 2` — старые клиенты не подходят.
