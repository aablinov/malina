## 1. Модель

- **Хост-авторитарная.** Бой считает браузер хоста комнаты. Сервер держит лобби, ретранслирует сообщения боя (не разбирая их) и хранит аккаунты, профили, комнаты и историю.
- **До четырёх героев** (`MAX_PLAYERS`, `src/bosses/scaling.ts`).
- **Один порт:** REST `/api/*` и WebSocket `/ws` на `node:http`. Если задан `STATIC=dist`, сервер отдаёт и саму игру — тогда игра и сервер на одном адресе.
- **Протокол общий** для клиента и сервера: `src/net/protocol.ts` содержит только типы и константы, `PROTOCOL = 1`. Если версия не совпала, соединение закрывается с кодом 4001.

## 2. Запуск

```
npm run server        # http://localhost:8787, база ./data/malina.db
PORT=9000 DB_PATH=/var/malina.db STATIC=dist npm run server
npm run server:test   # node:test, база в памяти
```

- Node ≥ 22.18 выполняет `.ts` сам (type stripping), сборки нет.
- В серверном коде нельзя писать свойства в параметрах конструктора и `enum`, а импорты — с расширением `.ts`. Проверка типов — `tsc -p tsconfig.server.json` (входит в `npm run typecheck`).
- SQLite — встроенный `node:sqlite`, без нативных зависимостей; WebSocket — пакет `ws`.
- Адрес сервера для игры: `?server=http://…` (запоминается в `malina.server`). Иначе берётся тот же адрес, если игру отдал сервер, иначе `http://localhost:8787`.

## 4. Схема SQLite

- `players` — id, имя, `name_key` (нижний регистр: NOCASE в SQLite не понимает кириллицу), хеш токена, время.
- `profiles` — `ProfileData` целиком в JSON и `version`.
- `rooms` — код из шести букв, хост, карта, `max`, `private`, `state` (`lobby | battle | closed`), сид.
- `room_members` — место, готовность, `gone_at`.
- `matches` — карта, число игроков, сид, начало и конец, результат (`won | lost | abandoned`), волна.
- `match_players` — место героя, малина и опыт за бой.

Время везде — миллисекунды Unix. Новая схема — только новой миграцией в конце списка.

## 5. Вход и профиль

- `POST /api/auth {name}` → `{playerId, name, token}`.
  - Имя — 2–16 букв, цифр, пробелов, `_` и `-`; без учёта регистра.
  - Занятое имя → 409. Своё имя со своим токеном — тот же герой.
- `POST /api/auth/rename`, `GET /api/me`. Токен хранится в `localStorage['malina.net']`; потерял токен — героя не вернуть, как и сохранение в localStorage.
- `GET /api/profile`, `PUT /api/profile {version, data}` — оптимистичная блокировка: по старой версии → 409 и свежий профиль.
- Проверка (`checkProfile`):
  - форма `ProfileData`, конечные неотрицательные числа, размер ≤ 256 КБ;
  - надето только то, что лежит в сумке;
  - неизвестные предметы выбрасываются, как в `Profile.load`.

  От читов в хост-модели это не защищает — отсекаем мусор.
- **Синхронизация** (`NetClient.syncProfile`, в лагере после возврата отложенной малины и снаряжения):
  - клиент помнит версию последней синхронизации (`malina.net.version`);
  - на сервере версия новее → берётся серверный профиль;
  - иначе на сервер уходит локальный;
  - дальнейшие изменения в лагере уходят с задержкой 0,8 с.

  Страница боя профиль не связывает: в бою он подменён набором обороны (`Profile.tdKit`).

## 6. Комнаты

- `GET /api/rooms` — публичные комнаты, где есть места: и в лобби, и в идущем бою (`RoomInfo.state`; это и есть `OnlineLobby` из `session.ts`).
- WebSocket: `room.create {map, max, private}`, `room.join {code}`, `room.leave`, `room.ready`, `room.map` и `room.kick` (только хост), `room.start` (хост, все гости готовы и на связи), `room.again` («Ещё раз» после боя — хост, тем же составом без готовности), `chat {text}` (всем в комнате: имя, место, текст ≤ 200 символов, не чаще раза в 0,4 с). Каждое изменение — `room.state {room, seats, you}` всем в комнате.
- **Старт:** `battle.start {matchId, map, players, seed, hostSeat, seats}`, строка в `matches`. Лагерь уходит на `?map=…&from=menu&players=N&room=КОД`, страница боя входит на сервер заново. «Ещё раз» — новый `battle.start`, страница боя уходит на него сама.
- **Вход в идущий бой:** `room.join` в комнату в бою, пока есть место, — строка опоздавшего в матче (для награды) и ему `battle.start`; у остальных его герой появляется по первому вводу и составу комнаты.
- **Друзья** (`friends`, миграция 003): `POST /api/friends {name}` — добавить по имени (список в одну сторону), `GET /api/friends` — на связи ли и в какой комнате (войти по коду — и в закрытую), `DELETE /api/friends?id=`.
- **Обрыв связи:**
  - место держится 30 с (`NET_LIMITS.graceMs`), повторный вход с тем же токеном возвращает на него (с перезагрузкой страницы «В бой» тоже так);
  - вход того же игрока с другой вкладки закрывает старое соединение (4009);
  - `hello` не пришёл за 15 с (страница боя занята постройкой карты) — закрыть с 4002, клиент переподключается и вход не забывает; 4003 — только неверный токен. Страница боя подключается сразу, без проверки `/api/health`;
  - ушёл хост: в лобби хостом становится следующий на связи. В бою — тоже следующий на связи (`battle.host {matchId, hostSeat}`), бой продолжается у него (раздел 7); обрыв хоста в бою ждёт только 5 с (`hostGraceMs`). Никого на связи — матч `abandoned`, комната снова лобби;
  - комната опустела — закрыта, код освобождается; закрытые удаляются через сутки.
- **Перезапуск сервера:** бои → `abandoned`, лобби остаются, все игроки считаются отключёнными, места держатся 10 мин. Страница боя переподключается, видит комнату в лобби — бой прерван («Связь с сервером прервалась»).
- **Лимиты:**
  - сообщение ≤ 64 КБ;
  - ≤ 100 сообщений в секунду; две секунды подряд сверх — закрыть (4008);
  - ввод гостя ≤ 60 в секунду, лишний отбрасывается.

## 7. Бой

- **Ретрансляция:** `relay {to?, d}`.
  - Гость → только хосту.
  - Хост → всем гостям или месту `to`.
  - Сервер добавляет `from` (место) и содержимое не смотрит.
  - Ввод гостя — `GuestInput` (сериализованный `KnightInput`, `src/knight.ts`).
- **Итог:** хост шлёт `battle.end {result, wave, rewards}`.
  - Сервер закрывает матч (повтор не засчитывается), обрезает награды и прибавляет их в профили (`Profile.addBerries`, `addXp`) одной транзакцией.
  - Затем рассылает `profile.updated` и `battle.over`; комната снова лобби, готовность заново.
  - Потолки: малина ≤ все награды волн карты × множитель партии (`crowdMult`), опыт ≤ 50 000.
- **История:** `GET /api/matches` (свои бои) и `GET /api/records?map=` (лучшая волна, победы, быстрейшая победа).
- **Общий бой** (`src/net/coop.ts`, страница боя с `&room=`; кто хост — из `battle.start`, `netBattle()`):
  - **хост** считает бой как одиночный и ведёт героев гостей (`Knight`) по их вводу. Мобы выбирают ближайшего героя на ногах (`src/party.ts`, `Mob.prey` через ту же подмену героя, что и приманки), удары по герою гостя — `party.hurt`. Без сил — встаёт через 2 с, как свой;
  - **снимок** хоста (`BattleSnap`, 20 раз в секунду): герои — место, взгляд, здоровье, ввод (перекат защёлкивается до снимка, лук — держит ПКМ); враги — сетевой id в стае (`Mob.net`), вид, место, здоровье, призван ли, атака (имя и номер `Mob.attackSeq`) и куда целится; оборона — `TowerDefense.snap()`: состояние, волна, отсчёт, идёт ли волна, куст, стены, башни по площадкам; кучки малины — номер и место;
  - **гость** ведёт своего героя сам, без задержки, и шлёт ввод 30 раз в секунду (`GuestInput`, с номером `seq` и пингом). Здоровье и «без сил» — хоста. **Сверка места:** хост возвращает в снимке последний учтённый ввод (`ack`); гость сравнивает место хоста с тем, где был сам, когда этот ввод ушёл, и убирает расхождение по 20 % за снимок (больше 2,5 м — сразу на место хоста). **Отброс** от удара моба хост шлёт гостю отдельно (`KnockMsg`) — герой гостя отлетает сразу и у него;
  - **буфер снимков:** у гостя чужие герои и куклы показываются с задержкой 0,1 с между двумя соседними снимками (`Track`) — неровная связь не дёргает;
  - **зоны и лава у хоста** — и для героев гостей: замедление от зон тех врагов, кто за ним гонится (`Pack.slowFor`, `Mob.target`), лава жжёт так же, как своего;
  - **враги у гостя — куклы** (`Mob.puppet`, `Pack.puppets`, `Pack.mirror`): мозга нет, место и взгляд со снимка, поза своя. Новая атака со снимка — кукла играет ту же атаку (`act`): замах, метки на полу, выпады, снаряды — в точку, куда целится моб у хоста, но никого не ранит, не ломает башни и никого не призывает. Оглушение, холод, знамя — по флагам снимка (`MOB_FLAG`), с теми же искрами; заморозка башни колдунчиком — тоже. Пропал из снимка — рассыпается. Удары гостя по куклам только вспыхивают;
  - **оборона у гостя** (`TowerDefense.remote`): волны не считает. `applySnap` проводит убыль куста, стен и башен их же уроном (трещины, обвал, руины), башни строит, растит и сносит. Меню площадки, починка стены и «волна сейчас» (G) уходят хосту командой `TdCommand` → `TowerDefense.command`.
- **Чужие герои со снаряжением.** Каждый игрок шлёт свой набор (`KitMsg`: предметы и надетое боя — набор обороны и купленное у маркитанта) раз в 3 с и сразу, как сменился; хост пересылает наборы всем. У каждого чужой герой — рыцарь со своим `Gear` по этому набору: оружие (свои числа удара — `Knight.tune`, общий `SWORD` у своего героя), броня и её здоровье, лук, артефакты, аура. Удар меча чужого героя считается его снаряжением (`strike(s, who, g)`: сила, крит, закалка).
- **Действия** (`Gear.onAction` → `ActMsg`): заряд заклинания (начал — видно, как набирает; сбросил), артефакт с зарядом и точкой, зелье, вспышка ауры, спец-удар (Q). Гость шлёт хосту, хост повторяет снаряжением героя гостя (`Gear.perform`: перезарядки, души и шкалы — того игрока, не проверяются) и пересылает остальным; свои — всем. Лук — флаг в вводе: снаряжение чужого героя стреляет само. У хоста всё это бьёт по-настоящему, у гостя — для вида. **Звуки** чужих героев (взмах, попадание, выстрел, заклинание) слышно ближе 14 м от своего.
- **Имена** над всеми героями (свой — золотой, без сил — бледнее): подписи поверх кадра (`Coop.drawNames`, `src/net/coop.css`).
- **Список игроков и чат** (`src/net/battle-ui.ts`): справа — имя, хост с короной, здоровье, пинг (меряется раз в 2 с, гости шлют свой в вводе, хост — в снимке); слева внизу — чат комнаты, Enter — написать, сообщения гаснут через 12 с; вход и выход игроков — строкой в чате.
- **Пауза** (Esc) в сетевом бою — только меню: время идёт, остальные играют. **«Ещё раз»** на итоге — у хоста новый бой всей комнате (`room.again`), у гостя — подсказка; посреди боя «заново» нельзя.
- **Новый хост посреди боя** (`battle.host`): гость на этом месте перехватывает бой с последнего снимка (`CoopGuest.promote` → `CoopHost`): оборона — `TowerDefense.takeOver` (группы волны, что ещё выходили, продолжают выходить — `TdSnap.queue`; куклы снова враги на своих дорогах — дорога и шаг марша в снимке, `Mob.unpuppet`), чужие герои — союзники, герой ушедшего убирается. Остальные гости слушают снимки нового хоста.
- **Малина у каждого своя** (`TowerDefense.personal`; в одиночной — как раньше, одна казна):
  - стартовая казна карты — каждому;
  - малина с врагов общая: кучки падают только у хоста, летят к ближайшему герою на ногах — кто подобрал, того и малина (`Props.collectors`: подобрал герой гостя — хост шлёт ему `GainMsg`). Гость видит кучки по снимку (`BattleSnap.piles`, `Props.mirrorBerries`), подобранные гаснут искрой; сбор урожая после волны тянет всё к ближайшему;
  - награда за волну — каждому как в одиночной, без множителя игроков (он был для общей казны): хост шлёт гостям `GainMsg` (`why: 'wave'`), у них — сбор урожая и баннер;
  - башни, улучшения, починка — за свою: гость платит сразу и шлёт `paid`; не вышло у хоста — возврат, продажа и бонус «волна сейчас» — ему же (`GainMsg`, `Purse` команды);
  - маркитант у гостя открыт — покупает за свою малину, купленное уходит в набор.
- **Итог и награда.** Хост шлёт `battle.end` по концу обороны (результат и волна — в историю). Награду каждый сдаёт сам — `battle.loot {matchId, berries, xp}`: собранная и не потраченная малина и опыт за бой, через 4,5 с после конца (сбор урожая долетает) или когда уходит со страницы боя. Сервер принимает её один раз за матч (`match_players.paid`), пока бой идёт или не позже 10 мин после конца, с потолком по карте (стартовая казна и все награды волн × множитель партии, втрое), и прибавляет в профиль. В лагере серверный профиль новее — он и берётся. Гость узнаёт итог из снимка или из `battle.over` (хост вышел — «бой прерван»).

## 8. Тесты

- `server/test/*.test.ts` (`npm run server:test`):
  - вход, переименование, профиль, конфликт версий, мусор;
  - комнаты, старт, ретрансляция, лимиты, итог и награды, своя награда за бой (`battle.loot`: один раз, потолок, окно);
  - вход в идущий бой, передача хоста в бою (уход и обрыв), «Ещё раз», чат, друзья;
