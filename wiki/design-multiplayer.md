# Сетевая игра — сервер

Версия 1.1 от 02.11.2026: общий бой обороны — хост ведёт героев гостей по их вводу, мобы бьют ближайшего героя, гость видит бой по снимкам хоста 20 раз в секунду и строит башни из общей казны командами хосту (раздел 7). Версия 1.0 от 02.11.2026: сервер на TypeScript и SQLite (`server/`): вход по имени и токену, профили героев на сервере, комнаты лагеря с кодом, готовностью и хостом, ретрансляция сообщений боя, итог и история боёв. Решения — [adr-001-dungeon-roguelite.md](adr-001-dungeon-roguelite.md) (хост-авторитарная модель), лагерь — [design-main-menu.md](design-main-menu.md), масштаб волн — [design-tower-defence.md](design-tower-defence.md), раздел 5.

## 1. Модель

- **Хост-авторитарная.** Бой считает браузер хоста комнаты. Сервер держит лобби, ретранслирует сообщения боя (не разбирая их) и хранит аккаунты, профили, комнаты и историю.
- **До четырёх героев** (`MAX_PLAYERS`, `src/bosses/scaling.ts`).
- **Один порт:** REST `/api/*` и WebSocket `/ws` на `node:http`. Если задан `STATIC=dist`, сервер отдаёт и саму игру — тогда игра и сервер на одном адресе.
- **Протокол общий** для клиента и сервера: `src/net/protocol.ts` содержит только типы и константы, `PROTOCOL = 1`. Если версия не совпала, соединение закрывается с кодом 4001.

## 2. Запуск

```
npm run server        # http://localhost:8787, база ./data/malina.db
PORT=9000 DB_PATH=/var/malina.db STATIC=dist npm run server
npm run server:test   # node:test, база в памяти
```

- Node ≥ 22.18 выполняет `.ts` сам (type stripping), сборки нет.
- В серверном коде нельзя писать свойства в параметрах конструктора и `enum`, а импорты — с расширением `.ts`. Проверка типов — `tsc -p tsconfig.server.json` (входит в `npm run typecheck`).
- SQLite — встроенный `node:sqlite`, без нативных зависимостей; WebSocket — пакет `ws`.
- Адрес сервера для игры: `?server=http://…` (запоминается в `malina.server`). Иначе берётся тот же адрес, если игру отдал сервер, иначе `http://localhost:8787`.

| `server/maps.ts` | карты с `meta.td` из `assets/maps`: какие можно выбрать и потолок малины за бой |

## 4. Схема SQLite

- `players` — id, имя, `name_key` (нижний регистр: NOCASE в SQLite не понимает кириллицу), хеш токена, время.
- `profiles` — `ProfileData` целиком в JSON и `version`.
- `rooms` — код из шести букв, хост, карта, `max`, `private`, `state` (`lobby | battle | closed`), сид.
- `room_members` — место, готовность, `gone_at`.
- `matches` — карта, число игроков, сид, начало и конец, результат (`won | lost | abandoned`), волна.
- `match_players` — место героя, малина и опыт за бой.

Время везде — миллисекунды Unix. Новая схема — только новой миграцией в конце списка.

## 5. Вход и профиль

- `POST /api/auth {name}` → `{playerId, name, token}`.
  - Имя — 2–16 букв, цифр, пробелов, `_` и `-`; без учёта регистра.
  - Занятое имя → 409. Своё имя со своим токеном — тот же герой.
- `POST /api/auth/rename`, `GET /api/me`. Токен хранится в `localStorage['malina.net']`; потерял токен — героя не вернуть, как и сохранение в localStorage.
- `GET /api/profile`, `PUT /api/profile {version, data}` — оптимистичная блокировка: по старой версии → 409 и свежий профиль.
- Проверка (`checkProfile`):
  - форма `ProfileData`, конечные неотрицательные числа, размер ≤ 256 КБ;
  - надето только то, что лежит в сумке;
  - неизвестные предметы выбрасываются, как в `Profile.load`.

  От читов в хост-модели это не защищает — отсекаем мусор.
- **Синхронизация** (`NetClient.syncProfile`, в лагере после возврата отложенной малины и снаряжения):
  - клиент помнит версию последней синхронизации (`malina.net.version`);
  - на сервере версия новее → берётся серверный профиль;
  - иначе на сервер уходит локальный;
  - дальнейшие изменения в лагере уходят с задержкой 0,8 с.

  Страница боя профиль не связывает: в бою он подменён набором обороны (`Profile.tdKit`).

## 6. Комнаты

- `GET /api/rooms` — публичные комнаты в лобби, где есть места (`RoomInfo`; это и есть `OnlineLobby` из `session.ts`).
- WebSocket: `room.create {map, max, private}`, `room.join {code}`, `room.leave`, `room.ready`, `room.map` и `room.kick` (только хост), `room.start` (хост, все гости готовы и на связи). Каждое изменение — `room.state {room, seats, you}` всем в комнате.
- **Старт:** `battle.start {matchId, map, players, seed, hostSeat, seats}`, строка в `matches`. Лагерь уходит на `?map=…&from=menu&players=N&room=КОД`, страница боя входит на сервер заново.
- **Обрыв связи:**
  - место держится 30 с (`NET_LIMITS.graceMs`), повторный вход с тем же токеном возвращает на него (с перезагрузкой страницы «В бой» тоже так);
  - вход того же игрока с другой вкладки закрывает старое соединение (4009);
  - `hello` не пришёл за 15 с (страница боя занята постройкой карты) — закрыть с 4002, клиент переподключается и вход не забывает; 4003 — только неверный токен. Страница боя подключается сразу, без проверки `/api/health`;
  - ушёл хост: в лобби хостом становится следующий на связи, в бою матч — `abandoned`, комната снова лобби;
  - комната опустела — закрыта, код освобождается; закрытые удаляются через сутки.
- **Перезапуск сервера:** бои → `abandoned`, лобби остаются, все игроки считаются отключёнными, места держатся 10 мин.
- **Лимиты:**
  - сообщение ≤ 64 КБ;
  - ≤ 100 сообщений в секунду; две секунды подряд сверх — закрыть (4008);
  - ввод гостя ≤ 60 в секунду, лишний отбрасывается.

## 7. Бой

- **Ретрансляция:** `relay {to?, d}`.
  - Гость → только хосту.
  - Хост → всем гостям или месту `to`.
  - Сервер добавляет `from` (место) и содержимое не смотрит.
  - Ввод гостя — `GuestInput` (сериализованный `KnightInput`, `src/knight.ts`).
- **Итог:** хост шлёт `battle.end {result, wave, rewards}`.
  - Сервер закрывает матч (повтор не засчитывается), обрезает награды и прибавляет их в профили (`Profile.addBerries`, `addXp`) одной транзакцией.
  - Затем рассылает `profile.updated` и `battle.over`; комната снова лобби, готовность заново.
  - Потолки: малина ≤ все награды волн карты × множитель партии (`crowdMult`), опыт ≤ 50 000.
- **История:** `GET /api/matches` (свои бои) и `GET /api/records?map=` (лучшая волна, победы, быстрейшая победа).
- **Общий бой** (`src/net/coop.ts`, страница боя с `&room=`; кто хост — из `battle.start`, `netBattle()`):
  - **хост** считает бой как одиночный и ведёт героев гостей (`Knight`) по их вводу. Мобы выбирают ближайшего героя на ногах (`src/party.ts`, `Mob.prey` через ту же подмену героя, что и приманки), удары по герою гостя — `party.hurt`. Удары гостей бьют врагов базовым уроном удара: снаряжение гостя хост не знает. Без сил — встаёт через 2 с, как свой;
  - **снимок** хоста (`BattleSnap`, 20 раз в секунду): герои — место, взгляд, здоровье, ввод (перекат защёлкивается до снимка); враги — сетевой id в стае (`Mob.net`), вид, место, здоровье; оборона — `TowerDefense.snap()`: состояние, волна, отсчёт, идёт ли волна, казна, куст, стены, башни по площадкам;
  - **гость** ведёт своего героя сам, без задержки, и шлёт ввод 30 раз в секунду (`GuestInput`). Здоровье и «без сил» — хоста; разошёлся с хостом дальше 1,5 м — встаёт на место хоста. Чужие герои — рыцари, шагают по вводу из снимка и подтягиваются к месту хоста;
  - **враги у гостя — куклы** (`Mob.puppet`, `Pack.puppets`): мозга нет, место и взгляд со снимка, поза своя; пропал из снимка — рассыпается. Удары гостя по куклам только вспыхивают, малина с павших у гостя не падает;
  - **оборона у гостя** (`TowerDefense.remote`): волны не считает. `applySnap` проводит убыль куста, стен и башен их же уроном (трещины, обвал, руины), башни строит, растит и сносит без казны. Меню площадки, починка стены и «волна сейчас» (G) уходят хосту командой `TdCommand` → `TowerDefense.command`, казна общая;
  - маркитант у гостя пока закрыт (казна хоста); лук, артефакты и спец-удары гостя — пока только для вида у него самого.
- **Итог** шлёт хост по концу обороны, награды пустые — бой попадает в историю, баланс наград не придуман. Гость узнаёт итог из снимка или из `battle.over` (если комната ушла в лобби раньше последнего снимка; хост вышел — «бой прерван»).
- **Дальше:** снаряжение гостя на хосте (урон, здоровье брони), его лук и артефакты, атаки кукол (замах и метка), имена над героями, маркитант гостя.

## 8. Тесты

- `server/test/*.test.ts` (`npm run server:test`):
  - вход, переименование, профиль, конфликт версий, мусор;
  - комнаты, старт, ретрансляция, лимиты, итог и награды;
  - обрыв и возврат, передача хоста, кик, вторая вкладка, перезапуск на файловой базе.
- `tests/net.spec.ts` (Playwright): настоящий сервер с базой в памяти и два браузера. Вход, комната по коду, «Готов», «Начать игру» — обе страницы в бою с `players=2`. Общий бой: герой гостя у хоста идёт по его вводу, гость строит башню через меню площадки из общей казны, враги волны хоста у гостя — куклы.
- `tests/menu.spec.ts`: без сервера панель показывает «Сервер недоступен», старт закрыт.
